Hemat Biaya Token AI: Konteks, Pembagian Model, Cache, Pelacakan

Terbit 2026-10-27

Jika Anda memakai model AI lewat API untuk pekerjaan nyata — agen pemrograman, pemrosesan dokumen, draf balasan dukungan — sebagian besar tagihan biasanya berasal dari token input yang sebenarnya tidak perlu dikirim. Panduan ini membahas empat kebiasaan yang memangkas biaya tanpa menurunkan kualitas jawaban, lengkap dengan harga daftar terkini agar Anda bisa menghitung sendiri.

1. Kirim hanya dokumen yang dibutuhkan tugas

Pemborosan yang paling umum adalah menempelkan seluruh repositori, manual, atau riwayat obrolan "jaga-jaga". Setiap permintaan membayar semuanya lagi.

  1. Cari dulu (grep, daftar file, atau indeks), lalu kirim hanya file atau bagian yang cocok.
  2. Pilih kutipan dengan nomor baris daripada file utuh.
  3. Untuk percakapan panjang, mulai percakapan baru dengan ringkasan tertulis singkat alih-alih membawa 100 giliran sekaligus.

2. Bagi pekerjaan menurut langkah dan model

LangkahTingkat model yang umum
Menyortir, memberi tag, mengekstrak kolom dataTerkecil
Menyusun draf, perubahan kode rutinMenengah
Perencanaan, debugging sulit, tinjauan akhirTerbesar

Dari tabel di atas, satu juta token input berharga $4 di Opus 5.5 dan $0.10 di Haiku 5.5 — selisih 40×. Uji kualitas pada sampel kecil sebelum menurunkan suatu langkah ke model yang lebih kecil: panggilan yang lebih murah tetapi butuh dua kali ulang tidak lebih murah.

3. Simpan file ringkasan proyek — dan cache

  • Tulis satu file singkat: proyek ini apa, struktur folder, konvensi, tujuan saat ini. Letakkan di bagian paling awal setiap permintaan.
  • Karena isinya tidak berubah antarpanggilan, file ini cocok untuk prompt caching: setelah penulisan pertama, pembacaan berharga $0.20, bukan $4 per juta token di Opus 5.5 — 5% dari harga input normal.
  • Taruh apa pun yang berubah (tanggal, pertanyaan pengguna) setelah bagian yang di-cache. Perubahan apa pun di bagian awal prompt akan merusak cache.

4. Lacak biaya per tugas, bukan per permintaan

  1. Catat token input, output, dan baca-cache dari kolom usage di setiap respons, dengan label nama tugas.
  2. Sekali seminggu, jumlahkan per tugas dan kalikan dengan harga di atas.
  3. Lihat tiga tugas teratas saja. Biasanya di situlah konteks yang terlalu besar atau model yang tidak sesuai bersembunyi.

Daftar periksa cepat

  • Apakah bagian prompt yang stabil berada di awal dan di-cache?
  • Apakah saya mengirim file utuh padahal kutipan sudah cukup?
  • Bisakah langkah ini dijalankan di model yang lebih kecil dengan kualitas sama?
  • Bisakah pekerjaan ini menunggu batch (diskon 50%)?

FAQ

Apakah menulis cache lebih mahal daripada input biasa?
Ya — di Opus 5.5, penulisan cache 5 menit berharga $5 dibanding $4 untuk input biasa. Biaya ini langsung terbayar begitu prefiks yang sama dibaca lagi.
Apakah batch selalu sepadan?
Hanya untuk pekerjaan yang tidak membutuhkan jawaban segera, seperti pemrosesan dokumen semalam.
