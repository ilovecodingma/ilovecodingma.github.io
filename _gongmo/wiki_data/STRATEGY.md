# 에이전트 위키 검색 유입 전략 (2026-11-27, 개발)
목표: 키워드 한두 개가 아니라 표제어·질문·계산·비교·시기별 등 여러 입구로 들어오게 한다.
1. 입구 6종 (문서 한 편에서 파생)
   - 표제어: 「퇴직금」(정의·요건·계산) — 위키백과·나무위키 검색 의도 흡수
   - 질문형: 「퇴직금 못 받으면」「연차 안 쓰면」— 토론 탭 제목을 질문으로
   - 계산형: 기존 계산기 링크 연결 (연말정산·퇴직금)
   - 비교형: 「퇴직금 vs 퇴직연금」「실업급여 vs 폐업 지원」
   - 시기형: 「2026 최저임금」「2025년 귀속 연말정산」— 해마다 개정 문서(역사 탭으로 신선도)
   - 용어사전: 문서 안 용어를 별도 짧은 표제어로 분리해 내부 링크
2. 주제 소싱: 나무위키·위키백과는 「어떤 표제어가 읽히는지」만 참고한다. 본문은 법령·공단·부처 원문으로 새로 쓰고 각주로 근거를 단다(복사 금지, 라이선스 때문).
3. 신선도: 매일 빌드 때 에이전트 교차검증 → 바뀐 문서만 개정(역사 탭), 최종 수정일 노출. 틀린 개정은 wiki_rollback.py 로 되돌림.
4. 내부 링크: 문서끼리 서로 링크(관련 제도), 문제은행·상태창 퀘스트·푸시에서 위키 문서로 연결.
5. 색인: 문서·토론은 색인, 역사·지난 개정판은 noindex. 사이트맵 자동 반영.
6. 사람 참여: 토론 탭 댓글 [수정제안] → 일일 검증 → 반영/기각 사유 기록. 참여자가 늘수록 재방문·공유가 는다.
홍보 협업 요청: (a) 신규 문서 URL 은 assets/wiki/index.json 과 sitemap 에 매일 반영 — 새 문서를 쇼츠/블로그/커뮤니티 답변에 링크, (b) 사람들이 많이 묻는 질문(커뮤니티·검색어)을 표제어 후보로 개발에 넘겨 주기(파일: _gongmo/wiki_data/_requests.txt 에 한 줄씩).
