- `홍보` 이름의 발신자가 데스크톱 세션들에 보낸 메시지 110건이 기록되어 있다(10/19 ~ 11/04, 받은 세션 7개). 메모리 `promo-laptop-split` 에 「홍보 실행은 노트북 「홍보」 세션만 한다」고 적혀 있어 이 발신자는 노트북 세션으로 보인다. 노트북 쪽 jsonl 은 이 PC 에 없으므로 그 세션의 작업량은 셀 수 없다. 이 PC 의 예약 런북 24개 세션(10/18~19)은 작업 스케줄러가 `claude -p` 로 실행한 것이다.

### 8-3. 루리 디퓨전 — 모델 파인튜닝 프로젝트

사용자의 프로젝트 하나를 여러 세션이 이어받아 진행했다. 결과물의 내용·표현은 다루지 않고, 작업 방식과 규모만 적는다.

- 세션 파일 18개(이름은 모두 「연출」), 활동일 31일(범위 안 25일), 기간 2026-10-07 ~ 2026-11-10. 전체 기간 발화 1,223, assistant 줄 31,938, 도구 호출 15,649회. 범위 안 발화 1,059, 도구 호출 14,074.
- 거의 모든 세션의 첫 지시가 「디퓨전 프로젝트를 파악해」·「인수인계 진행해」 계열이다. 한 세션의 컨텍스트가 차면 새 세션을 열어 프로젝트를 다시 파악하게 한 방식으로, 약 한 달 동안 세션이 순차로 이어졌다(세션 안 컨텍스트 이어받기 요약 76회는 별도). 프로젝트 판단 권한은 10/14 에 세션이 위임받았고(메모리 `ruri-diffusion-owner`) 규약(삭제 전 장부 기록, 학습 푸시 2중 승인)은 그대로 유지했다.
- **모델·방식.** 기록에 나타난 모델 계열은 SDXL 기반 체크포인트(도구 입력에 SDXL·Pony·NoobAI·Illustrious 같은 이름이 등장)이고 방법은 LoRA 추가 학습이다. 도구로는 diffusers 를 쓰고 ComfyUI 도 언급된다. 별도 시도로 영상 생성 모델(Wan 2.2 5B 계열)도 돌려 보았으나 10/28 에 보류했다(아래).
  - 도구 호출 입력에 해당 문자열이 든 호출 수(범위 안 합계): lora 1569, vram 531, pony 476, kaggle 365, sdxl 228, noob 197, diffusers 143, r2 84, train 60, wan 19, illust 8, comfy 3.
- **학습 횟수·기간.** Kaggle 학습 실행 이름(고유 시각 접미사)이 세션 기록에 나온 서로 다른 값은 전체 54개(9/12~11/06)이고, 표 범위(10/12~11/09) 안은 27개다. 날짜별(범위 안): 10/13 3, 10/14 3, 10/15 1, 10/29 5, 10/30 5, 10/31 2, 11/02 1, 11/03 2, 11/04 1, 11/05 2, 11/06 2. 이름이 기록에 나온 횟수라 실제로 성공한 학습 수와 같지 않을 수 있다(같은 이름은 1회로 셈).

- **Kaggle 학습 / 로컬 생성 분리.** 10/29 총괄 지시로 「LoRA 학습은 로컬 GPU 가 아니라 Kaggle 로 넘기고, 생성은 로컬」로 정해졌다. 이유는 이 PC 가 반복해서 꺼지는 상태라 2시간 풀부하 학습이 위험을 키운다는 것이었다(메모리 `feedback-train-on-kaggle`, `pc-crash-raptorlake-ram`). 학습 결과 체크포인트는 클라우드 저장소(R2 버킷)에 올려 두며, 11/02 에 그 버킷의 읽기·쓰기가 살아 있음을 확인했고 과거 학습 체크포인트 38개가 남아 있었다고 적혀 있다. 도구 입력에 R2 관련 문자열이 든 호출은 범위 안 84회.
- **GPU·VRAM 제약.** 로컬 GPU 는 RTX 4070 Ti, 메모리 12GB(`nvidia-smi` 로 확인, 12,282 MiB). Kaggle 쪽 GPU 로는 T4 가 기록에 자주 나온다(언급 152행). 영상 생성 모델은 가중치와 활성값이 약 13GB 라 12GB 카드에 올라가지 않아 CPU 오프로드를 켜야 했고 그 결과 스텝 속도가 39배 느려졌다. 사용자가 10/28 에 영상 축을 보류하고 모델(약 32GB)을 지웠으며, 재개 조건은 VRAM 16GB 이상으로 기록돼 있다(메모리 `wan-bg-memory-reap`).
